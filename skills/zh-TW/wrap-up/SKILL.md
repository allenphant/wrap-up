你現在被觸發了 `wrap-up` 技能。請直接執行以下兩個步驟，不需要向我確認。

**本技能所稱的「專案根目錄」**：本次 session 實際載入的 `AGENTS.md` / `CLAUDE.md` 所在的那個目錄；兩者都不存在時，用目前的工作目錄。不要在上層目錄或其他位置另建新檔。

### 步驟一：更新專案偏好 (AGENTS.md)

請回顧本次對話，如果我（使用者）有提出任何新的「通用開發偏好、程式碼風格要求、或特定習慣」（例如：指定使用的套件、特定的寫法規範），請將這些新規則 **附加 (Append)** 到專案根目錄的 `AGENTS.md` 檔案中。

* 如果 `AGENTS.md` 不存在，請建立它。
* **⚠️ 絕對不要在未經使用者確認的情況下刪除或覆蓋 `AGENTS.md` 中原有的內容。** 預設行為只有「在檔案最後新增」。
* 寫入後**回讀檔案尾端確認內容真的落地**，不要只因為指令沒有報錯就當作成功。
* 如果本次對話沒有新的偏好，跳過本節的寫入，但**下面的整併檢查與指標檔維護仍然要做**。

#### 整併檢查（append 之後做，防止 AGENTS.md 無限膨脹）

寫入後掃描整份 `AGENTS.md`，找出以下三類問題：

1. **重複**：同一條規則以不同措辭出現多次，或多個標題底下講同一件事。
2. **矛盾**：新規則與既有規則衝突（例如新的說「一律用 X」，舊的說「不要用 X」）。
3. **過時**：規則提到的檔案、指令、工具或版本已經不存在或已被取代。

**發現問題時絕對不要自行刪改。** 請列成清單交給使用者，每一項說明：在哪幾行、屬於哪一類、建議怎麼處理、為什麼。等使用者逐項確認後才動手。

* 使用者沒有回應或沒有明確同意的項目，**一律維持原樣**。
* 實際刪改時只針對確認過的段落做最小修改，**不要重寫整份檔案**，改完回讀驗證。
* 如果沒發現任何問題，簡單說一句「整併檢查無異常」即可，不要為了有事做而硬找。

#### 指標檔維護（每次都要檢查，即使本次沒有新偏好）

`AGENTS.md` 是唯一真相來源。但 Claude Code 只會讀取 `CLAUDE.md`，**不會**自動探索 `AGENTS.md`（實測於 Claude Code 2.1.252），因此專案根目錄必須有一個 `CLAUDE.md`，內容**只有**以下這一行：

```
@AGENTS.md
```

（Codex 等原生讀取 `AGENTS.md` 的工具並不需要這個檔案。它的存在純粹是為了相容 Claude Code，對其他工具無害。）

請依序處理：

1. **先檢查 symlink。** 用 `ls -la` 或 `stat` 確認 `CLAUDE.md` 與 `AGENTS.md` 是否為 symlink。
   只要其中任何一個是，**先 `rm` 掉那個 symlink 本身**（刪除連結不會動到目標檔），再把它應有的內容寫成真實檔案。
   **絕對不可以寫入 symlink** —— 寫入連結等於寫入目標檔，會把整份規則覆蓋成一行，並變成自我遞迴的 import。
2. `CLAUDE.md` 不存在 → 直接建立成上面那一行。
3. `CLAUDE.md` 存在但內容不只那一行（被 `/init` 覆寫，或被其他 agent 追加了規則）→
   **先把多出來的內容原封不動、一字不漏地 append 到 `AGENTS.md`**，回讀確認搬完之後，
   才把 `CLAUDE.md` 覆寫成那一行。
   **不要自行判斷哪些內容「有價值」而略過任何一段** —— 判斷錯就是靜默刪掉別人寫的規則。
4. **絕對不要把規則本身寫進 `CLAUDE.md`** —— 那會製造出第二份會走樣的副本。

### 步驟二：更新專案狀態快照 (CURRENT_STATE.md)

在專案根目錄下更新（或建立） `CURRENT_STATE.md` 檔案。每一次執行此指令，都請直接**覆寫**該檔案，保持專案只有一份最新狀態。

**覆寫前請先讀取現有的 `CURRENT_STATE.md`（若存在）。** 如果某個段落在本次對話中完全沒有進展（例如這次沒有失敗的嘗試、沒有新的決策），請**保留上一版該段落的內容**，不要寫成「無」或整段刪除 —— 否則一次短對話就會洗掉長期累積的脈絡。

請嚴格使用以下 Markdown 結構進行精煉：

# [一句話總結：正在做什麼 + 目前狀態（完成/進行中/卡住），寫法像 git commit message]

> **更新時間**：YYYY-MM-DD HH:MM
> **專案核心**：一句話描述專案目標與主要技術棧

## 本次對話目標

(這段對話原本要完成什麼)

## 已完成任務

* **[任務簡述]**：(關鍵改動摘要)
  * `修改的檔案路徑1`
  * `修改的檔案路徑2`

## 進行中與卡點 (In Progress & Blockers)

* **目前進度**：(做到哪裡了)
* **下一步**：(準備做什麼)
* **卡點 (Blocker)**：(卡住的原因，若無則填「無」)

## 避坑指南 (Failed Approaches)

* **嘗試過的方法**：(具體作法)
  * **為什麼失敗**：(錯誤報錯或邏輯缺陷)
  * **教訓**：(接下來絕對不要再走這條路)

## 關鍵決策 (Key Decisions)

* **[決策項目]**：(做了什麼決策，例如資料庫選型、架構設計)
  * **原因**：(為什麼這樣決定)
  * **被否決的方案**：(當初沒選的其他方案)

## 交接備忘錄 (Handover Context)

(寫給下一個完全沒有前文的 AI 實體。包含目前的技術脈絡，以及你強烈建議它接手後第一步該輸入什麼指令、或是先看哪個檔案。)

---

完成後，請簡單回覆我你更新了哪些檔案、是否在 AGENTS.md 中新增了規則、整併檢查的結果，並且直接給我可以在下一個對話直接啟動的第一句話。例如：「請閱讀`CURRENT_STATE.md`跟上進度，接下來我們要做...」，其中`CURRENT_STATE.md`要給我絕對路徑。
