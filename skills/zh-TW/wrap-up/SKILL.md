# Wrap-up

維持兩份預設開工入口：`AGENTS.md` 保存長期規則與任務文件入口，`CURRENT_STATE.md` 保存最新交接。`CLAUDE.md` 僅作相容指標；專案既有規格按任務讀取，不預設新增另一份狀態或決策文件。

分兩階段執行：階段一直接完成保存；階段二只處理使用者核准的規則整併與文件封存。已有明確授權的項目不重複詢問。其他工作可繼續，未核准的刪改維持待審。

## 位置與邊界

- 專案根目錄使用本次 session 載入的專案層 `AGENTS.md`／`CLAUDE.md` 所在目錄；兩者皆不存在時使用目前工作目錄。不因繼承上層指引而把專案狀態寫到上層。
- 歷史保存在根目錄下 `docs/wrap-up/`。不得把封存檔作為目前規則或狀態來源。
- 沿用專案的資料、秘密與操作限制；保存與交接不擴大存取權限，不把敏感值寫入規則或快照。

## 階段一：直接保存，再提出審核清單

### 1. 附加新偏好

先讀 `AGENTS.md`，只附加本次對話中使用者真正新增、尚未記錄的長期偏好；沒有新偏好就略過寫入。不存在時建立。

此階段不得改寫、刪除或自行整併既有規則。不要把執行日誌、臨時卡點、業務題目狀態或代理自行推測的偏好加入規則。寫入後回讀確認。

### 2. 維護相容指標

`AGENTS.md` 是專案規則來源；`CLAUDE.md` 的完整內容僅為 `@AGENTS.md` 加換行。

1. 先檢查兩檔是否為 symlink，絕不直接寫入連結。需換成一般檔時，先安全讀取並保存既有內容，再移除連結本身、建立同內容的一般檔；不得改動連結目標。目標不可讀或越過允許的存取範圍時，停止依賴該內容的操作並回報。
2. `CLAUDE.md` 不存在就建立單行指標。
3. 若另有內容，先將指標之外的原文完整附加至 `AGENTS.md`，不得自行篩掉規則；回讀確認內容已完整保存，才把 `CLAUDE.md` 改為單行指標。若只缺末尾換行，直接補齊，不重複搬移。
4. 回讀確認兩檔均為一般檔、規則未遺失且指標正確。

### 3. 保存上一版狀態

覆寫前先完整讀取 `CURRENT_STATE.md`，存在時逐位元複製到 `docs/wrap-up/states/YYYY-MM-DD-HHMM.md`，時間取該檔的更新時間；沒有時間則取 mtime。

同名快照存在且內容相同時沿用；內容不同時加數字後綴另存，絕不覆蓋既有快照。回讀比對內容一致後才更新根目錄狀態。快照失敗時不得覆寫。若狀態檔是 symlink，先遵守上節的安全保存與轉為一般檔流程。

### 4. 精煉最新狀態

保留仍有效的事實，不要求沿用舊段落的完整措辭。這次沒有進展的未解決事項仍須保留，不能寫成「無」或默默丟掉；舊的已完成歷史由快照承接。

使用下列六段名稱與順序，頂端另放一句話狀態標題、更新時間及一句話專案核心：

| 段落 | 保留原則 |
| --- | --- |
| 本次對話目標 | 最新工作目標；使用者只是補充或詢問時，延續原目標。 |
| 已完成任務 | 與目前工作相關的少量成果及證據位置；不逐輪堆積修改清單。 |
| 進行中與卡點 (In Progress & Blockers) | 全部未解決事項；舊支線縮成一句，保留狀態、恢復／完成條件與必要證據入口。 |
| 避坑指南 (Failed Approaches) | 仍可能再次發生的問題、原因及避坑方法。 |
| 關鍵決策 (Key Decisions) | 接下來工作必須知道的決策摘要與必要來源。 |
| 交接備忘錄 (Handover Context) | 接手第一步、成功判準與按任務閱讀的文件。 |

可直接使用這個結構，不保留括號內的說明文字：

```markdown
# [目前工作與狀態]

> **更新時間**：YYYY-MM-DD HH:MM
> **專案核心**：[目標與主要技術]

## 本次對話目標

## 已完成任務

## 進行中與卡點 (In Progress & Blockers)

## 避坑指南 (Failed Approaches)

## 關鍵決策 (Key Decisions)

## 交接備忘錄 (Handover Context)
```

**字元軟預算：1,500～2,500。** 計數使用完整 UTF-8 文字解碼後的 Unicode code point 數，例如 Python `len(text)`，包含標題、標點、空白、換行、Markdown 與路徑；不是 byte 數或 token 數，也不要求為達下限填字。

超出先刪重複敘述與歷史細節、合併同類支線並引用既有證據。不得截斷、刪除未決事項、安全條件或接手必要決策來達標；仍超出時保留必要內容並說明原因。不要為壓字數新增平行狀態文件。

詳細 log 留在 run 產物。狀態只留結論、適用範圍與證據入口；區分「已決策」「已實作」「已驗證」，不可把局部驗證寫成整體完成。

寫入後回讀並檢查：六段順序、實際字元數、舊版每項未決事項的去向、必要決策／安全條件，以及本次新增的證據入口。完成、取消或取代的事項只有在對話或證據支持時才移出未決清單。必要文件缺失就記錄缺失，不改以歷史封存代替。

### 5. 提出有證據的審核清單

只檢查與本次工作相關的項目，不為了清單遍讀整個專案歷史。此步只提報，不改規則、不搬文件。

- **A 類規則**：`AGENTS.md` 的重複、矛盾或有證據的過時規則。
- **B 類文件**：對話已明確確認作廢／被取代／不再維護；或實際搜尋確認無引用，且有歷史命名或明確後繼版本。搜尋須符合專案工具優先序，非程式文件可用 `rg`；將引用搜尋範圍與排除項說清楚，不把「找不到引用」單獨當作過時證據。
- 不提報根目錄三份核心檔或 `docs/wrap-up/` 內的歷史證據，不因 `legacy` 命名就認定不用。

每項列出 ID、行號／相對路徑、類別、具體證據與理由，並明確呈現**變更前／變更後**，讓使用者不用自己推想「核准會發生什麼」。文件引用數必須來自實際搜尋，不猜測。

- **A 類**：
  - 變更前：逐字引用要改動的原文，標明 `AGENTS.md` 行號；重複或矛盾時，連同對照的另一條一併引用並標行號。
  - 變更後：整併／修正後的完整新文字；若是移除，寫「移除，原文逐字移至 `docs/wrap-up/ARCHIVE.md`」。
  - 效果：一句話說明規則意思有沒有改變（例如「僅合併措辭，適用範圍不變」）。
- **B 類**：
  - 變更前：目前路徑，以及引用搜尋的範圍與結果（`references in repo: N`，並列出命中的檔案）。
  - 變更後：封存路徑 `docs/wrap-up/files/<原始相對路徑>`；有引用要修正時，列出「哪個檔案第幾行、改成什麼」。
  - 還原：一句話說明如何搬回原位。

若全無發現，回報「整併檢查無異常」，跳過階段二並提供啟動句。

有項目時，先以文字印出完整證據清單，再在**同一輪對話內**用 `AskUserQuestion` 取得核准，不要把提問留到下一輪。`AskUserQuestion` 是延遲載入工具，需先 `ToolSearch select:AskUserQuestion` 載入。

- **總開關與分題放在同一次呼叫**：一次呼叫帶多題，第 1 題固定是總開關，第 2 題起直接是分題勾選。不得先單獨問總開關、等回答後再問分題。
- **第 1 題（總開關，單選）**：`question` 問「清單上的 N 項要怎麼處理？選『全部核准』或『全部不核准』時，其他題不用答，可直接 Submit。」三個選項：
  - 「全部核准」：套用文字清單上的**每一項**（含本次呼叫放不下的），忽略其他題的勾選，不再追問。`description` 要列出全部 ID 與動作，寫成「變更前：… → 變更後：…」。
  - 「依後面各題勾選」：只套用分題中勾選的項目。
  - 「全部不核准」：全部維持原樣，忽略其他題的勾選，不再追問。
- **第 2 題起（分題）**：每題 `multiSelect: true`，A 類、B 類各自成題。選項要讓人不看上方清單也能判斷：
  - `question`：用完整句說明「核准後會發生什麼」，例如「以下規則整併／封存項目，核准後 `AGENTS.md` 會變動，原文先逐字存入 `ARCHIVE.md`。要套用哪些？」。
  - `label`：ID 加動作與對象，例如「A1 移除第 40–44 行（與第 12 行重複）」「B2 封存 docs/old-design.md」。
  - `description`：固定寫成「變更前：… → 變更後：…」，各一句、含具體行號或路徑。
  - 某題只有 1 個項目時，補一個「不套用（維持原樣）」選項，以符合每題至少 2 個選項。
- 第 1 題未回答但分題有勾選時，勾選的項目視為核准。
- 一次呼叫最多 4 題、每題最多 4 個選項，所以第一次呼叫是總開關加最多 3 個分題。項目超出時分批：依證據強度排序；第 1 題選「依後面各題勾選」或只勾了分題時，接著問下一批（只含分題），全部在本次對話內問完，不得略過未問的項目。
- 未勾選、勾選「不套用（維持原樣）」、取消或整份無回應，一律視為未核准，原樣保留，不追問。
- 「全部核准」只涵蓋提問前已用文字印出的項目；之後新發現的項目要另外取得核准。
- 總開關或勾選的結果即為授權，ID 對應文字清單；記錄授權時寫「使用者於 YYYY-MM-DD 在 wrap-up 選單核准」。
- 非互動情境（`claude -p`、hook 觸發等無法使用選單）退回：停在清單，說明本技能要求核准後才刪改，不提供啟動句。

## 階段二：套用核准項目

1. 只處理階段一選單中選「全部核准」涵蓋或明確勾選（或使用者以文字明確核准）的項目；未回應、表示不確定或否決的項目維持原樣。沒有核准項目時不追問，直接提供啟動句。
2. **規則整併／移除前**：將所有要改寫或移除的原文逐字附加至 `docs/wrap-up/ARCHIVE.md`，記錄日期、類別、來源、授權與原因；回讀確認完整保存後再改 `AGENTS.md`。保留適用範圍與例外，不因整併改變規則意思。
3. **文件封存前**：檢查引用並修正目前入口。移到 `docs/wrap-up/files/<原始相對路徑>`，保留目錄結構；受 Git 追蹤者用 `git mv`，未追蹤者用一般移動。目標存在時另取不衝突位置，不覆蓋；記錄原路徑、封存路徑、日期與原因。外部文件不因此獲得搬移或修改授權。
4. 不得封存根目錄 `AGENTS.md`、`CLAUDE.md`、`CURRENT_STATE.md` 本身，也不得再封存 `docs/wrap-up/` 內的內容。保存上一版副本不屬於移走根檔。
5. 首次有規則／文件封存時，在 `AGENTS.md` 加一次 archive 入口；已有等效入口不重複加。封存目錄的 README 簡述歷史用途與目前來源，不另建平行狀態。
6. 回讀修改與封存內容、核對未核准項目原樣保留、指標未損壞、引用可用。
7. 依階段一的快照規則先保存目前狀態，再更新 `CURRENT_STATE.md` 的時間、相關成果及下一步；仍使用六段與軟預算。

## 完成回覆

簡短說明更新哪些檔案、是否附加新規則、封存什麼，以及尚待完成的事項。提供下一個對話可直接貼上的啟動句，使用 `CURRENT_STATE.md` 的絕對路徑：

> 請閱讀 `/absolute/path/to/CURRENT_STATE.md` 跟上進度，接著依交接備忘錄完成下一步。
