你現在被觸發了 `wrap-up` 技能。

本技能分成兩個階段：**階段一不需要任何確認，直接做完**；階段二要等我回覆之後才執行。

**本技能所稱的「專案根目錄」**：本次 session 實際載入的 `AGENTS.md` / `CLAUDE.md` 所在的那個目錄；兩者都不存在時，用目前的工作目錄。不要在上層目錄或其他位置另建新檔。

**封存位置**：專案根目錄下的 `docs/wrap-up/`（不存在就建立）。

---

# 階段一：立刻寫入，然後提出審核清單

以下 1-1 到 1-4 全部直接執行，不要問我。做完 1-5 之後停下來等我回覆。

## 1-1 更新專案偏好 (AGENTS.md)

回顧本次對話，如果我（使用者）提出了任何新的「通用開發偏好、程式碼風格要求、或特定習慣」（例如：指定使用的套件、特定的寫法規範），請將這些新規則 **附加 (Append)** 到專案根目錄的 `AGENTS.md`。

* `AGENTS.md` 不存在就建立它。
* **⚠️ 這個階段只能新增，絕對不可以刪除或改寫任何既有內容。** 所有刪改一律留到階段二、經我核准後才做。
* 寫入後**回讀檔案尾端確認內容真的落地**，不要只因為指令沒有報錯就當作成功。
* 本次對話沒有新偏好就跳過寫入，但 1-2 之後的步驟照做。

## 1-2 指標檔維護（每次都要檢查）

`AGENTS.md` 是唯一真相來源。但 Claude Code 只會讀取 `CLAUDE.md`，**不會**自動探索 `AGENTS.md`（實測於 Claude Code 2.1.252），因此專案根目錄必須有一個 `CLAUDE.md`，內容**只有**這一行：

```
@AGENTS.md
```

（Codex 等原生讀取 `AGENTS.md` 的工具不需要這個檔案。它純粹是為了相容 Claude Code，對其他工具無害。）

依序處理：

1. **先檢查 symlink。** 用 `ls -la` 或 `stat` 確認 `CLAUDE.md` 與 `AGENTS.md` 是否為 symlink。
   只要其中任何一個是，**先 `rm` 掉那個 symlink 本身**（刪除連結不會動到目標檔），再把它應有的內容寫成真實檔案。
   **絕對不可以寫入 symlink** —— 寫入連結等於寫入目標檔，會把整份規則覆蓋成一行，並變成自我遞迴的 import。
2. `CLAUDE.md` 不存在 → 直接建立成上面那一行。
3. `CLAUDE.md` 存在但內容不只那一行（被 `/init` 覆寫，或被其他 agent 追加了規則）→
   **先把多出來的內容原封不動、一字不漏地 append 到 `AGENTS.md`**，回讀確認搬完之後，才把 `CLAUDE.md` 覆寫成那一行。
   **不要自行判斷哪些內容「有價值」而略過任何一段** —— 判斷錯就是靜默刪掉別人寫的規則。
4. **絕對不要把規則本身寫進 `CLAUDE.md`** —— 那會製造出第二份會走樣的副本。

## 1-3 封存上一版狀態快照

如果 `CURRENT_STATE.md` 已存在，**先把它複製到** `docs/wrap-up/states/YYYY-MM-DD-HHMM.md`（用該檔案自己記載的更新時間；沒有就用它的 mtime）。

這一步**不需要我核准** —— 它是保存，不是刪除。沒有這一步，下一步的覆寫會直接丟掉歷史。

## 1-4 更新專案狀態快照 (CURRENT_STATE.md)

在專案根目錄更新（或建立） `CURRENT_STATE.md`，直接**覆寫**，讓專案只保留一份最新狀態。

**覆寫前先讀取現有內容。** 如果某個段落在本次對話中完全沒有進展（這次沒有失敗的嘗試、沒有新的決策），**保留上一版該段落的內容**，不要寫成「無」或整段刪除 —— 否則一次短對話就會洗掉長期累積的脈絡。

請嚴格使用以下 Markdown 結構進行精煉：

# [一句話總結：正在做什麼 + 目前狀態（完成/進行中/卡住），寫法像 git commit message]

> **更新時間**：YYYY-MM-DD HH:MM
> **專案核心**：一句話描述專案目標與主要技術棧

## 本次對話目標

(這段對話原本要完成什麼)

## 已完成任務

* **[任務簡述]**：(關鍵改動摘要)
  * `修改的檔案路徑1`
  * `修改的檔案路徑2`

## 進行中與卡點 (In Progress & Blockers)

* **目前進度**：(做到哪裡了)
* **下一步**：(準備做什麼)
* **卡點 (Blocker)**：(卡住的原因，若無則填「無」)

## 避坑指南 (Failed Approaches)

* **嘗試過的方法**：(具體作法)
  * **為什麼失敗**：(錯誤報錯或邏輯缺陷)
  * **教訓**：(接下來絕對不要再走這條路)

## 關鍵決策 (Key Decisions)

* **[決策項目]**：(做了什麼決策，例如資料庫選型、架構設計)
  * **原因**：(為什麼這樣決定)
  * **被否決的方案**：(當初沒選的其他方案)

## 交接備忘錄 (Handover Context)

(寫給下一個完全沒有前文的 AI 實體。包含目前的技術脈絡，以及你強烈建議它接手後第一步該輸入什麼指令、或是先看哪個檔案。)

## 1-5 產出審核清單（只列清單，不要動任何東西）

檢查兩類對象。**這個階段一個字都不准改、一個檔案都不准搬。**

### A 類：`AGENTS.md` 裡的規則

1. **重複** —— 同一條規則以不同措辭出現多次，或多個標題底下講同一件事。
2. **矛盾** —— 兩條規則互相衝突（例如一條說「一律用 X」，另一條說「不要用 X」）。
3. **過時** —— 規則提到的檔案、指令、工具或版本已經不存在或已被取代。

### B 類：專案裡過時的文件與資料檔

**只在有具體證據時才提報**，符合以下任一條件：

* 本次對話中明確講過它已經作廢、被取代、或不再維護；
* 或：全 repo 搜尋不到任何地方引用它（用 `grep -rl <檔名>` 確認），**且**檔名帶有日期、`old`、`legacy`、`deprecated`、`backup`、`_bak`、`archive` 之類的字樣，或存在明顯的後繼版本。

**不要為了湊數而列**，也不要列出你只是「覺得」可能沒用的東西。寧可漏報也不要誤報。

### 清單格式

每一項都要寫出：

* **位置** —— `AGENTS.md` 的行號範圍，或檔案的相對路徑
* **類別** —— 重複／矛盾／過時
* **證據** —— 矛盾要指出跟哪一條衝突；檔案要附上 `repo 內引用次數：N`（實際跑過 grep 的數字，不要用猜的）
* **建議動作** —— 封存到哪裡
* **理由** —— 一句話

### 然後停下來

列完清單就**停止**，等我回覆。**這個階段不要給下一個 session 的第一句話。**

**如果 A、B 兩類都沒有任何發現**：說一句「整併檢查無異常」，**跳過階段二，直接給我第一句話**（格式見階段二最後一節）。不要為了走完流程而製造一次沒必要的往返。

# 階段二：套用核准項目，然後給第一句話

我回覆之後才執行。

1. **只處理我明確核准的項目。** 我沒提到的、我沒回應的、我說不確定的，**一律維持原樣**。
2. **規則封存**：把該段規則**原文一字不漏**寫進 `docs/wrap-up/ARCHIVE.md`（append，附上封存日期、類別、來源），**確認寫入並回讀之後**，才從 `AGENTS.md` 移除那一段。
3. **檔案封存**：移到 `docs/wrap-up/files/<原始相對路徑>`，**保留原本的目錄結構**（例如 `docs/old-design.md` → `docs/wrap-up/files/docs/old-design.md`），這樣要復原時路徑是明確的。
   * repo 有 git 就用 `git mv`，保留檔案歷史。
   * 每搬一個檔案就在 `ARCHIVE.md` 記一筆：`原路徑 → 封存路徑`、日期、原因。
4. **絕對不可以封存 `AGENTS.md`、`CLAUDE.md`、`CURRENT_STATE.md` 本身**，也不可以封存 `docs/wrap-up/` 底下的任何東西。那會讓整套機制當場失效。
5. **第一次建立封存時**，在 `AGENTS.md` 最後加一行（只加這一次，之後不要重複加）：
   `> 已封存的規則與文件見 docs/wrap-up/ARCHIVE.md。`
6. 全部改完後**回讀驗證**：確認該搬的搬了，以及**不該動的都還在**。
7. 更新 `CURRENT_STATE.md` 的「更新時間」，並在「已完成任務」補一條記錄本次封存了什麼。
8. 給我第一句話（見下）。

**如果我回「都不用改」、或答非所問、或沒有核准任何一項** —— 什麼都不要改，直接跳到第一句話。不要追問，不要卡住。

### 第一句話

最後請簡單回覆我：更新了哪些檔案、是否在 `AGENTS.md` 新增了規則、封存了什麼，然後直接給我可以在下一個對話貼上就啟動的第一句話。例如：

> 請閱讀 `/absolute/path/to/CURRENT_STATE.md` 跟上進度，接下來我們要做⋯⋯

其中 `CURRENT_STATE.md` 要給我**絕對路徑**。
